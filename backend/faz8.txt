# 0. PROJENİN GENEL VİZYONU

## Proje adı

**Taskozz**

## V1'in amacı

TaskFlow; hem **kişisel görev yönetimi** hem de **kurumsal birim içi görev yönetimi** için kullanılabilecek, web tabanlı, gerçek bir full-stack uygulamadır.

Kurumsal senaryo:

> Bir kurumun/birimin şefi, personellere görev verebilir, görevlerin durumunu takip edebilir ve birimin genel iş durumunu görebilir.

Staj defterindeki anlatım:

> **TaskFlow, kurumsal birimlerde yönetici ve personel arasındaki görev dağılımını, görev takibini ve görev durumlarının izlenmesini sağlayan web tabanlı görev yönetim sistemidir.**

Örneğin:

```text
BURULAŞ
└── X Birimi
    └── Şef
        ├── Personel
        ├── Personel
        └── Personel
```

Ancak TaskFlow **BURULAŞ'a hard-code edilmiş bir uygulama değildir.**

Aynı uygulama kişisel kullanım için de çalışabilir.

---

# 1. TASKFLOW'UN İKİ KULLANIM MODU

## A. Kişisel kullanım

Kişi TaskFlow'u kendi görevlerini yönetmek için kullanabilir.

```text
TaskFlow
└── Kişisel Kullanıcı
    ├── Task
    ├── Task
    ├── Task
    └── Task
```

Bu hesapta:

* kendi görevini oluşturabilir
* deadline belirleyebilir
* priority belirleyebilir
* status değiştirebilir
* görevlerini arayabilir
* filtreleyebilir
* sıralayabilir
* pagination kullanabilir
* history görebilir
* dashboard kullanabilir

**Burada ADMIN/ŞEF yoktur ve gerekmez.**

---

## B. Kurumsal kullanım

Örneğin:

```text
BURULAŞ
└── X Birimi
    └── ADMIN / ŞEF
        ├── USER / PERSONEL
        ├── USER / PERSONEL
        └── USER / PERSONEL
```

Buradaki teknik roller:

```text
ADMIN = Şef / Birim yöneticisi
USER  = Personel
```

### Önemli:

Ayrı:

```text
CHIEF
MANAGER
COACH
EMPLOYEE
```

rolleri **V1'de oluşturulmayacak.**

İki temel role sahip olmak bilinçli bir sadeleştirmedir.

# 3. ROLLER

## ADMIN / ŞEF

Kurumsal kullanımda yöneticidir.

Temel amacı:

> **"Birimimdeki işler ne durumda?"**

ADMIN:

* personelleri görebilir
* personel oluşturabilir
* personel yönetebilir
* görev oluşturabilir
* görev atayabilir
* görevleri takip edebilir
* dashboard üzerinden genel durumu görebilir
* personellerin görevlerini inceleyebilir
* görev taleplerini inceleyebilir
* görev taleplerini kabul/reddedebilir

---

## USER / PERSONEL

Temel amacı:

> **"Benim yapmam gereken işler neler?"**

Kurumsal USER:

* login olur
* kendi profilini görür
* kendi profilindeki izin verilen bilgileri günceller
* kendisine atanmış görevleri görür
* görevlerini günceller
* görevleri tamamlar
* search/filter/sort/pagination kullanır
* deadline/priority görür
* task history görür
* kendi dashboard'unu görür
* yeni bir iş/görev talebinde bulunabilir

### Kritik karar:

Kurumsal USER, **kendi kafasına göre doğrudan kurumsal Task oluşturmaz.**

Bunun yerine:

```text
USER
 ↓
Görev Talebi
 ↓
ADMIN / ŞEF
 ↓
Kabul
 ↓
Gerçek Task
```

# 5. TASK REQUEST — GÖREV TALEBİ

V1'e dahil edilecek.

## Önerilen veri modeli

```text
TaskRequest
├── id
├── title
├── description
├── priority
├── due_date
├── requested_by
├── status
├── reviewed_by
├── reviewed_at
├── review_comment
└── created_at
```

### Status

```text
PENDING
APPROVED
REJECTED
```

---

## `requested_by`

Talebi oluşturan personeldir.

Örneğin:

```text
requested_by = Ahmet
```

---

## `reviewed_by`

Talebi değerlendiren şeftir.

Bunun amacı:

> "Bu talebi kim onayladı/reddetti?"

sorusunun cevaplanabilmesidir.

---

## `reviewed_at`

Kararın verildiği zamanı tutar.

---

## `review_comment`

Özellikle red durumunda şefin açıklama yazabilmesini sağlar.

Örneğin:

> "Bu görev mevcut plan içerisinde bulunuyor."

# 6. TASK REQUEST → TASK DÖNÜŞÜMÜ

Personel:

```text
title:
Araç bakım raporunu hazırla

priority:
HIGH

due_date:
30 Ağustos
```

talep eder.

Database:

```text
TaskRequest
status = PENDING
requested_by = Ahmet
```

Şef kabul ederse:

```text
TaskRequest
status = APPROVED
reviewed_by = Şef
reviewed_at = ...
```

ve gerçek Task oluşturulur:

```text
Task
title = ...
description = ...
priority = HIGH
due_date = ...
assigned_to = Ahmet
created_by = Şef
```

### Önemli mantık

Talebi yapan:

```text
requested_by = Ahmet
```

Görevi resmileştiren:

```text
created_by = Şef
```

Görevi yapacak:

```text
assigned_to = Ahmet
```

Bu ayrım bilinçli.
