# 1. REGISTER

## Hedef

```text
/register
    ↓
Public Registration
    ↓
USER
    ↓
Login
    ↓
Dashboard
```

### Yapılacak

* `/register` frontend
* Public register backend endpoint
* Kullanıcı oluşturma
* Password hashing
* Public register'dan oluşturulan kullanıcı = `USER`
* Kullanıcı kendisini `ADMIN` yapamaz
* Register sonrası Login
* Login sonrası Dashboard

### Kesin sınır

```text
Public Register
      ↓
     USER
```

**Public Register → ADMIN YOK.**

Kurumsal ADMIN hesabı ayrı kurumsal başlangıç/kurulum mantığıyla oluşturulur.

Master dokümanda public register'ın USER oluşturması ve ADMIN'in public olarak seçilememesi açıkça belirtiliyor. 

---

# 2. KİŞİSEL / KURUMSAL HESAP AYRIMI ⭐

## V1'in en kritik kalan işi

Hedef veri modeli:

```text
                    KİŞİ
                      │
             ┌────────┴────────┐
             ↓                 ↓
       BİREYSEL HESAP     KURUMSAL HESAP
             ↓                 ↓
           USER           ADMIN / USER
             ↓                 ↓
     Kişisel Tasks       Kurumsal Tasks
```

Aynı kişi:

```text
Ahmet
 ├── Bireysel USER hesabı
 └── Kurumsal USER hesabı
```

kullanabilir.

### Kesin kural

```text
Bireysel Task
      X
Kurumsal Task
```

birbirine karışmayacak.

Örneğin:

```text
Bireysel:
- İngilizce çalış
- Fatura öde
- Spor yap
```

kurumsal ADMIN'in dashboardunda **görünmeyecek**.

### Teknik kural

Bu ayrım:

❌ sadece frontend dropdown'u olmayacak.

Gerçek:

* database
* model
* migration
* authentication/account bağlamı
* task sorguları
* authorization

üzerinde uygulanacak.

Master dokümanda kişisel ve kurumsal kullanımın birbirinden ayrılması kesin karar olarak belirtiliyor.

# 4. KURUMSAL USER → TASK REQUEST

Bu mevcut çalışan sistemdir ve **bozulmayacak**.

```text
Kurumsal USER
      ↓
Task Request
      ↓
PENDING
      ↓
ADMIN
   ┌──┴──┐
   ↓     ↓
APPROVE REJECT
   ↓     ↓
 TASK  REJECTED
```

Approve:

```text
requested_by = USER
created_by   = ADMIN
assigned_to  = USER
```

Reject durumunda:

```text
review_comment
```

tutulabilir.

Bu V1 kapsamındadır.
